## 트러블슈팅

### 1. 라벨 ZIP 한 번에 3~5분
- **문제** 조 꼬리표(라벨) 이미지를 ZIP으로 받는 데 서버 상황에 따라 3~5분. 이미지 1장마다 Chromium을 새로 띄우는 구조(`node-html-to-image`)
- **대안** 동시 실행 수만 늘리기(브라우저 실행 비용은 그대로, 메모리 부담 증가) vs **브라우저 풀 재사용 + 페이지 큐**
- **선택 이유** 가장 큰 비용은 렌더링이 아니라 브라우저를 띄우는 일 자체
- **해결**
  - `createBrowserPool`로 브라우저를 미리 띄워 재사용, 브라우저별 `p-limit` 페이지 큐
  - 환경별 동시성: 운영 8×2 · 개발 4 · 로컬 2 — 실험 커밋(`e76fa60`, `eaf8e79`)으로 값을 바꿔 가며 측정
  - PNG → JPEG(q80), 대기 조건 `networkidle0` → `domcontentloaded`
  - 건당·전체 타이머(`console.time` / `performance.now`)를 코드에 넣어 직접 측정
- **결과** 전체 ZIP **3~5분 → 약 22.8초**, GBS당 이미지 생성 평균 약 1초. 이 코드는 2026년 수양회에서도 그대로 사용

### 2. 행사 일주일 전, EC2에서만 이미지 생성 실패
- **문제** 로컬에서 되던 이미지 생성이 운영 서버에서만 실패 (06-26, 수양회 07-02)
- **원인 후보** Puppeteer가 받은 Chromium의 서버 실행 불가 · 리눅스 권한/sandbox 제약 · 느린 서버의 타임아웃
- **해결** production에서 시스템 Chromium 경로(`/usr/bin/chromium-browser`) 지정, `--no-sandbox` · `--disable-setuid-sandbox`, 타임아웃 연장, `Promise.allSettled`로 일부 실패가 ZIP 전체를 막지 않게 변경 (`f6dbf88`, `40586fa`, `1cfcc9d`)
- **결과** 수양회 기간 라벨·QR 출력 정상

### 3. (실수) 잘못 병합한 PR을 되돌리다 팀원 코드까지 되돌림
- PR #90을 2025-06-21 21:50 병합 → 잘못된 커밋이 섞여 69분 뒤 revert
- 그 병합에 섞여 있던 팀원의 숙소(dormitory) 모듈 5개 파일까지 되돌아감 → 팀원이 다음 날 복구
- **배운 점** 머지 커밋을 되돌릴 땐 영향 범위를 먼저 확인하고, PR은 기능 단위로 쪼갠다

## 기술 선택 이유

| 기술 | 이유 |
|---|---|
| Puppeteer 브라우저 풀 | 라벨 디자인을 HTML 템플릿 그대로 이미지로 만들 수 있고, 풀로 재사용하면 실행 비용을 한 번만 냄 |
| QR 멱등 발급 | 이미 발급된 QR은 다시 만들지 않아 재요청이 몰려도 S3 저장본과 DB가 어긋나지 않음 |
| DB 좌표 템플릿 (`qr_metadata`) | QR·글자 위치를 DB로 관리해 템플릿이 바뀌어도 코드 수정 불필요 |
| S3 + CloudFront | 버킷을 공개(ACL)하지 않고 CloudFront로만 이미지 제공 |
| ChatGPT 페어 프로그래밍 | 병목 분석·대안 비교는 ChatGPT와 함께, 동시성 값과 운영 서버 대응은 직접 실험으로 결정 |

## 회고

- **잘한 점** 감으로 동시성 값을 정하지 않고 실험 커밋으로 환경별 값을 측정해 정했다
- **아쉬운 점** 운영 서버와 같은 환경에서 미리 돌려 보지 않아 행사 직전에 장애를 만났고, 인증 기능은 끝까지 완성하지 못해 팀원이 마무리했다
- **다음에는** 운영과 같은 환경에서 먼저 검증하고, PR은 기능 단위로 작게 나눈다
